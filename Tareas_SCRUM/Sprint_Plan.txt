CAPACIDAD Y REGLA DE TIEMPO
---------------------------------------------------------------------
  Si una tarea se atrasa mas de 2 horas, avisar al Scrum Master.
  Si el viernes a las 18:00 algo no funciona: RECORTAR (ver abajo).
  No iniciar tareas nuevas despues del viernes 20:00. Solo cerrar y grabar.

ORDEN DE RECORTE SI FALTA TIEMPO (de menor impacto a mayor)
---------------------------------------------------------------------
  1. Streamlit en vez de React (solo si el backend ya funciona).
  2. Un solo modelo ML clasico, sin tuning.
  3. SCD Tipo 1 en vez de Tipo 2.
  4. Alertas solo en el dashboard (sin SMTP).
  5. GenAI solo con Ollama local y una herramienta de consulta.

NUNCA RECORTAR (lo mas penalizado por la rubrica)
---------------------------------------------------------------------
  - Staging con trazabilidad (raw separado de preparado).
  - Modelo dimensional con grano declarado.
  - KPIs validados con consulta SQL independiente.
  - Baseline del modelo ML y evaluacion en datos no usados.
  - README reproducible y repo sin secretos.

RIESGOS DEL SPRINT
---------------------------------------------------------------------
  Dependencia no instalada -> resolver en Sprint 0, no el viernes.
  Data leakage en ML -> dividir por fecha, nunca aleatorio en series.
  Frontend conectado directo a SQL -> prohibido, usar la API.
  Cifras inventadas por la IA -> solo vistas/consultas parametrizadas.
  Secretos en el repo -> usar .env y .env.example.
